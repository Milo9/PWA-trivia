# App audit — 2026-10-31

Follow-up: the user selected items **1, 2, 5, and 6**, which are now implemented.
The numbered findings below describe the original audit; items 3, 4, 7, 8, and 9
remain suggestions. The initial development-server fix is retained.

Scope: local source, game rules, persistence, feedback delivery, service worker,
development server, question validation, and Chromium browser flows. No deployment
or live Firebase writes were performed. This is not a factual review of all questions
or a real-device Safari audit.

## Fixed

**High — development server exposes repository files to the network.**
`scripts/serve.js` previously bound to all interfaces and served any file beneath
the repository, including `.git/config`, tooling, and local drafts. Its string-prefix
directory check also admitted sibling paths sharing the repository's name prefix.
Malformed percent escapes threw outside an error handler and terminated the server.

The server now binds to localhost, permits only public PWA asset paths, checks
resolved and real filesystem containment, rejects malformed URLs with HTTP 400,
and restricts methods to GET/HEAD. A regression test covers public assets, internal
files, encoded traversal, invalid encoding, null bytes, Windows separators, missing
files, HEAD, and continued operation after malformed requests. README updated.

## Suggested work, pending selection

1. **Medium — validate saved data before restoring it.** `loadActiveRound()` only
   parses JSON, and `tryResumeActiveRound()` assumes fields such as
   `currentCategoryIds` and `answers` exist. In Chromium, saving
   `{ "roundQuestions": [{}] }` produced an uncaught `Cannot read properties of
   undefined (reading 'map')`. Add versioned schema validation and recovery for
   rounds, stats, preferences, Quick Play settings, and feedback queue items.
   Report storage/quota failures instead of silently implying progress is saved.

2. **Medium — show offline readiness and download failures.** Service-worker
   registration/installation failures are silent in `app.js`; users can start
   playing before all question files are cached. Add a visible downloading/ready/
   failed state and a retry action, so travel preparation can be verified in-app.
   Add automated failed-install and old-to-new-build update tests.

3. **High hardening — authenticate and limit feedback writes.** The checked-in
   Firebase rules accept unauthenticated creation of schema-valid reports, with no
   rate limit. The device ID is client supplied rather than authenticated identity.
   Add authenticated ownership and server-enforced abuse limits. This assessment is
   of repository rules; deployed rules and actual abuse were not verified. Requires
   coordinated backend configuration and migration, so it was not changed locally.

4. **Medium — preserve keyboard focus and expose selection state.** Category
   selection rebuilds all cards. In Chromium, focusing a card and pressing Enter
   moved focus to BODY. Category cards and settings toggles also lack accessible
   selected/pressed state. Preserve focus or update existing nodes, add appropriate
   semantics, and move/announce focus when changing screens/questions. Verify with
   VoiceOver on the target iPhone as well as keyboard navigation.

5. **Medium — prevent silent feedback loss at queue limits.** `enqueue()` drops
   oldest reports above 200, while their reported IDs can remain marked as already
   reported. Permanently invalid reports are moved to a debug-only failure log.
   Reject new reports when full or explicitly offer a choice; expose failed reports
   with retry/export rather than silently leaving users unable to resubmit.

6. **Medium — coordinate multiple tabs and guard repeated transitions.** Feedback
   and stats use localStorage read/modify/write operations without cross-tab
   coordination; simultaneous writes can overwrite each other. `advanceToNext()`
   also lacks an answered-question guard and `showResults()` records a game on
   every call. Add transaction/locking semantics and idempotent round completion,
   with tests for duplicate events and simultaneous tabs. These are code-review
   risks; normal single-tab browser flows passed.

7. **Content quality — triage existing warnings and accuracy coverage.** Validation
   reports 24,507 questions, zero errors, and 394 advisory warnings. These include
   possible duplicates and unusual question lengths; a warning is not proof of an
   incorrect question. `npm run audit -- status` reports 5,152 questions outside
   current chunks and prior completed coverage, and `audit/backlog.json` contains
   unresolved duplicate leads. Fold uncovered questions into the audit and resolve
   the backlog, then verify uncertain claims against sources.

8. **Enhancement — export/import personal progress.** Provide a versioned backup
   for stats, seen-question history, and preferences, plus a separate explicit
   repeat-history reset. This would protect long-term progress when changing phones
   or clearing browser storage.

9. **Enhancement — make the category picker easier to scan.** Add category search
   and optional sorting by name, question count, or personal accuracy. There are
   currently 19 categories; the picker and repeated question-bank footer require
   substantial scrolling on a phone.

## Follow-up implementation: items 1, 2, 5, 6

- Added version-aware validation for legacy/current saves and safe reconstruction
  of scores, lives, and resume position. Malformed reports stay exportable. Save
  and quota failures are visible, including a retry after restoring a completed
  round whose results could not be saved.
- Added prominent offline progress, verified readiness, download retry and cache
  repair. Failed updates preserve the previous offline build. File hashes prevent
  accepting mismatched build contents; stalled downloads time out.
- Full report queues reject new submissions instead of dropping existing ones.
  Failed reports remain in the queue with retry/export controls; legacy failures
  migrate without truncation. Original malformed values are included in exports.
- Shared mutations use IndexedDB transactions as the authoritative source, with
  localStorage mirrors and optional Web Locks. This also handles stale mirrors
  before storage events arrive. Mirrors restore on launch. Each round has a
  separate save and revision; stale tabs cannot overwrite it. Completion identities
  prevent duplicate stats, and duplicate answer/Next events are ignored.
- Added `npm run reliability-check` for corruption/export, full/failed queues,
  concurrent reports/results with and without Web Locks, missing mirrors, stale
  tabs, quota/reload/result-save retries, interrupted installs, active-cache repair,
  and failed/successful updates. It uses no live database writes.

Follow-up verification: 42 unit tests pass, plus reliability, feedback, and visual
browser checks. The category and quiz screenshots were inspected. App-shell hashes
were refreshed with `npm run stamp`. No question data or backend configuration was
changed, and nothing was deployed.
