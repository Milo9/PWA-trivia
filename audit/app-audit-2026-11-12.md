# App and tooling audit — 2026-11-12

Scope: app code (`app.js`, `sw.js`, `storage-logic.js`, `game-logic.js`,
`feedback-queue.js`, `index.html`, CSS unused-selector scan), build/ship/stamp
tooling, `validate.js`, the dev server, unit tests and the three Playwright
suites, docs, and local leftovers from earlier agent sessions. Skimmed only, not
reviewed in depth: `audit.js`, `check-draft.js` internals, `analyze.js`,
`find-gaps.js`, the `feedback-*` scripts, `templates/`. No real-device iOS test.
The October audit's open items are carried into the list below.

## Fixed in this pass

- **Finishing a round and then pressing ✕ or Back no longer throws the result
  away.** Reproduced in Chromium first. A survival run that ended on the last life,
  followed by ✕, was discarded with no confirm and never reached stats. Back from
  the same point deferred the save to the next launch. A fully answered standard
  round, followed by ✕ or Back, said "progress will be lost" and discarded it.
  All four paths now record the round and show results. Mid-round quit still asks
  for confirmation, and a round whose result failed to save still falls back to
  the quit confirm. `reliability-check` scenario [5b] covers this.
- **`validate` went from ~70s to ~0.6s with identical output.** The all-pairs
  near-duplicate loop (~300M comparisons) is replaced by exact Jaccard prefix
  filtering. Output was diffed byte-for-byte against the old run, and a unit test
  compares it to brute force on random sets, including the empty-set case.
- **`validate` now enforces the app's hard limits as errors**: question length ≤
  600 characters, option length ≤ 300, and the id pattern (max 64 characters).
  Saved-round validation and the Firebase rules already rejected anything outside
  these, which would have made a round unrestorable and a report unsendable. The
  id check used to be only a warning. The corpus has no current offenders.
- **`ship.js` failure handling.** A failed `git commit` used to report
  "Nothing to commit" and exit 0; it now exits 1. After a failed push, a rerun
  used to say "Nothing to ship"; it now pushes the unpushed commits.
- **The browser suites refuse to run on stale `sw.js` hashes.** Previously an
  unstamped edit to `app.js` made the offline-install scenarios time out after
  30s with no explanation. They now say "run `npm run stamp`" up front.
- **`data/topics.json` is out of the cache hash and the dev-server allowlist.**
  It's a dev-only file the app never loads, but editing it pushed an app update
  to phones.
- **Constant drift removed.** `storage-logic.js` hardcoded 3 lives, a 150-question
  cap, and `[10,20,30,40]`. The round sizes are now single-sourced (`app.js`
  reads them from `StorageLogic`), and a unit test keeps the other two equal to
  `GameLogic`.
- **Small fixes:**
  - `civics-law-economics` had no category icon and fell back to 🎯.
  - The survival subtitle said "You cleared the entire category!" for what is a
    run of at most 150 questions, possibly across several categories.
  - The home screen re-parsed stats about 40 times per render; it now loads them
    once.
  - Removed the always-null `dropped` field from `applyOutcome`.
  - Updated the manifest's stale "17 categories".
  - README: project layout, testing notes, and new-category steps (icon/color
    entries are needed).
  - Removed the empty `scratchpad_local/`.

Judgment calls you may want to veto:
- ✕ or Back after the final answer now shows results instead of quitting.
- A malformed question id is now a `validate` error, not a warning.
- The browser suites refuse to run until `npm run stamp` has been run.

Leftover sweep coverage: a mechanical scan of every app module and script found

Verification: 45 unit tests, `validate` (0 errors, same 394 warnings),

## For discussion

1. **CLAUDE.md is ~124KB (~30k tokens) and loads into every session.** Medium-high
   severity given the token-efficiency preference; medium effort. Most of it is
   per-session narrative, which its own header says it shouldn't be. Proposal:
   condense it to the durable rules (~15–25KB) and move the war stories to a
   non-auto-loaded `docs/lessons.md`, or drop them. Needs your review.
2. **`ship` always bumps the build.** Low-medium severity; small effort. A
   docs-, template-, or tooling-only ship still changes `version.json`, so phones
   get an "update ready" toast for nothing. Proposal: bump and stamp only when a
   served file's hash changed.
3. **Offline install on very slow connections.** Low-medium severity; medium
   effort. All ~26 files download in parallel, each with a 30s wall-clock timeout.
   Gzipped, the whole set is ~1.7MB (6.3MB raw), so below roughly 0.45 Mbps the
   transfer can't finish inside the timeout and the install fails every time. This
   only matters for a first install or a ship that changes most files, since
   unchanged files copy forward from the old cache. A retry or repair also
   re-downloads files already fetched into the new cache. Proposal: cap
   concurrency (~4) and reuse cached entries whose hash already matches.
4. **Storage growth.** Low severity today; small-medium effort.
   `stats.completedRoundIds` gains an id per game forever and is re-parsed on
   every stats read. The IndexedDB lock store keeps an empty `round:<id>` record
   for every round ever played. Both act as dedupe tombstones against stale tabs,
   so capping or pruning needs a deliberate rule (e.g. keep the last 500 ids; prune
   round records whose localStorage key is gone).
5. **Hard dependency on IndexedDB (reproduced).** Medium-low severity; medium
   effort. With `indexedDB.open` blocked in Chromium, Start Round does nothing.
   The screen stays on settings, and the only feedback is "Couldn't safely update
   saved data…". The app becomes unplayable instead of degrading to "progress
   won't be saved". Typical iOS Safari has IndexedDB, so this mostly affects
   locked-down or storage-disabled browsers.
6. **394 standing `validate` warnings bury new ones.** Medium severity for the
   content workflow; small-medium effort. Proposal: a reviewed-warnings baseline so
   `validate` reports "N new" separately.
7. **No CI.** Low-medium severity; small effort. Tests and validate only run inside
   a local `ship`. A GitHub Actions job (`npm test` + `validate`, now under 2s
   total) would catch a push from elsewhere.
8. **Architecture weight.** Discussion only. `app.js` is ~2,450 lines. The October
   hardening added an IndexedDB + localStorage-mirror + Web Locks transaction layer
   to every answer, for multi-tab safety on what is a single-user phone PWA. It's
   tested and working. The alternative is single-tab ownership (a "this app is open
   in another tab" notice), which would remove most of that layer.
9. **Still open from the October audit:**
   - #3 Firebase auth and rate limiting (high hardening).
   - #4 Keyboard focus and `aria-pressed` on category cards and toggles.
   - #7 Content warnings and audit orphans (e.g. business-brands 761,
     catchphrases 1002, tv-catchphrases 800).
   - #8 Progress export/import.
   - #9 Category search/sort.
10. **Legacy-compatibility paths.** Small effort, but only safe once no old
    saves remain on your devices. The code still handles the pre-October
    `offline-trivia:active-round` key, the `offline-trivia:feedback-failed` list,
    and saves without a `v` field. If your phones have run a post-October build
    and finished or discarded any old round, these paths can probably go.
11. **Local leftovers (gitignored, never shipped).** `dev-screenshots/` holds agent
    one-off scripts and logs: `implement-*.py`, `format-recovery.py`,
    `audit-check.cjs`, `verify-deploy.cjs`, `chromium-*-debug.log`,
    `deploy-validation.log`. They're safe to delete, but that's your call.
    `questions_inbox/processed/` (148 files, 6.7MB) is kept intentionally per the
    README.

## Follow-up implementation: items 1–5, 10, 11

The user selected items 1, 2, 3, 4, 5, 10 and 11. Items 6–9 remain suggestions.

1. **CLAUDE.md condensed from 124KB to ~19KB** (about 31k to under 5k tokens per
   session). The previous file is preserved verbatim in `docs/lessons-learned.md`,
   which is not auto-loaded. Every command, flag, threshold and do-not-re-flag id
   was checked as still present. Template pointers to sections that now exist only
   in the archive were repointed. CLAUDE.md states a ~25KB budget: new rules go in
   as short entries, incident write-ups go in the archive.
2. **`ship` bumps the build only when a served file changed** (app shell,
   `sw.js`, `icons/`, `data/categories.json`, `data/questions/`), detected from
   `git status` against HEAD. It also never bumps twice after a failed commit.
   Unit-tested (`test/ship.test.js`).
3. **Offline install:**
   - The 30s total timeout is now a stall timeout (restarts whenever bytes arrive).
   - At most 4 files download at once.
   - A retry or repair reuses hash-verified files already in the target cache.
   - `categories.json` is no longer downloaded twice.
   - Reliability [6] asserts a retry and a repair each re-download only the
     missing file. [6b] asserts a 4.5s trickled download succeeds under a 1.5s
     stall timeout, and a 3s stall fails and recovers on retry.
   - Writing these tests exposed a real race: a fast retry could finish installing
     before the app checked, so the app then asked the now-active worker to
     "repair" an already complete cache, a redundant second download pass. Retry
     now asks for the active worker's status first.
4. **Storage growth:**
   - `completedRoundIds` is capped at the 500 most recent (`StorageLogic`).
   - A lingering save whose round is already counted is deleted through the lock,
     so it can't resurface once its id ages out.
   - Lock records now carry `updatedAt`. Empty `round:<id>` records older than 24h
     (or with no timestamp) are pruned at launch; fresh ones stay as tombstones.
5. **No IndexedDB:**
   - If IndexedDB fails to open, or doesn't open within 3s, the session runs on
     localStorage alone with a notice.
   - A flag makes the next launch with IndexedDB reseed from localStorage instead
     of rolling back. Mutation-tested: without the reseed, stats revert from 3
     games to 1.
   - Reliability [5d] covers blocked and hung opens.
10. **Legacy paths:**
    - The pre-November `active-round` save and `feedback-failed` list are migrated
      once at launch (`migrateLegacyStorage`), and their scattered read paths are
      removed.
    - Malformed legacy data stays exportable.
    - Unversioned prefs/stats are still accepted on purpose: they're only rewritten
      on a toggle or a game, so rejecting them would silently reset them.
    - Dead fallbacks for answers without ids and saves without settings were
      removed. Reliability [5c] covers the migration.
11. **Deleted from `dev-screenshots/`:** the agent scripts and logs listed in
    item 11. Older screenshots from past sessions (`resume-*`, `survival-*`,
    `live-build-324-offline.png`) were left, since they weren't in the approved list.

Post-ship review fix (build 327): a legacy round migrated by build 326 had no
`revision`, so its first answer after resuming tripped the "changed in another
tab" check. The migration now writes `revision: 0`, and the check treats a
missing stored revision as 0 (covering saves 326 already migrated). Each half
was verified on its own, and [5c] now plays on after resuming and after a reload.
The streamed download also falls back to `arrayBuffer()` where `response.body`
isn't available.

behavior of the streamed download, the 3s IndexedDB timeout, and the live
325→327 upgrade path needs one manual pass. Open the app on wifi, take the
update, confirm the build number and "Ready to play offline", and play a round.
